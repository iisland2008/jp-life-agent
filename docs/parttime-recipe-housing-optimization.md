# 打工助手、留学生食谱与租房避坑：个人开发者功能优化规格

> 用途：交给 Claude 优化“打工助手 / 留学生食谱 / 租房避坑”三个模块。
>
> 目标用户：在日本生活、以中文为主要使用语言的留学生。
>
> 核心约束：不依赖企业认证、平台专属 API 或大规模第三方数据抓取；涉及劳动、食品安全和租赁条款时只做信息辅助，不代替政府机关、律师、医生或其他专业人员的判断。
>
> 文档日期：2026-08-06

---

## 1. 总体产品原则

三个模块都不应只是普通聊天问答入口，而应优先提供普通问答 AI 不擅长的能力：

- 持续保存用户自己的记录。
- 根据时间生成提醒和待办。
- 将规则转成检查表、计算器和状态流程。
- 保存照片、工资单、合同、票据等个人证据。
- 将复杂日文转成可确认的字段。
- 给出官方来源和最后核对日期。
- 允许用户导出自己的数据。

禁止把系统输出包装成确定的法律、医疗或食品安全结论。

统一提示语建议：

```text
本功能用于整理信息和辅助确认，不构成法律、医疗、营养或专业意见。
重要事项请以官方资料、合同原文及专业机构答复为准。
```

# 2. 打工助手

## 2.1 功能定位

帮助留学生管理多个兼职的工时、工资、合同和沟通记录，并在出现需要进一步确认的情况时，整理事实并提供官方咨询入口。

系统不应：

- 自动判断雇主违法。
- 判断用户一定符合某项在留资格要求。
- 替用户向雇主、入管或劳动部门提交信息。
- 提供自动规避工时限制的方法。

## 2.2 留学生工时记录器

支持同时记录多个兼职：

```text
本周资格外活动

便利店      12小时
居酒屋       8小时
翻译兼职     6小时
────────────────
合计        26/28小时

剩余：2小时
```

基础字段：

```json
{
  "jobId": "job_001",
  "jobName": "便利店",
  "workDate": "2026-08-06",
  "startTime": "18:00",
  "endTime": "23:00",
  "breakMinutes": 30,
  "paidMinutes": 270,
  "isSchoolLongHoliday": false,
  "note": ""
}
```

实现要求：

- 多份兼职合并计算。
- 跨周班次按日期和时间拆分。
- 休息时间与实际计薪时间分开。
- 长期休假日期由用户根据学校校历录入。
- 接近用户设定上限时显示黄色提醒。
- 超出用户设定上限时显示红色“请确认”，但不能直接判定违法。
- 规则旁显示来源、适用对象和最后核对日期。

官方参考：

- [出入国在留管理厅：资格外活动许可](https://www.moj.go.jp/isa/applications/guide/nyuukokukanri07_00045.html)
- [入管厅：新入国外国人指引](https://www.moj.go.jp/isa/support/guidance/index.html)

## 2.3 工资估算与工资单检查

用户可以手动输入或通过 OCR 辅助录入：

```text
工作地区：东京
总工时：62小时
基本工资：¥74,400
交通费：¥5,000
深夜工时：8小时
显示时薪：¥1,200
```

检查项目：

- 实际基础时薪。
- 交通费是否被计入工资比较。
- 工资单工时是否与用户记录差异过大。
- 是否存在用户未理解的扣款项目。
- 所在都道府县最低工资及生效日期。
- 深夜、加班、休息时间是否需要进一步确认。

推荐文案：

```text
发现 2 个可能需要确认的项目
```

禁止文案：

```text
你的雇主违法了
你一定可以获得赔偿
```

最低工资数据来源：

- [厚生劳动省：地域别最低工资全国一览](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/koyou_roudou/roudoukijun/minimumichiran/index.html)

最低工资配置必须包含：

```json
{
  "prefecture": "東京都",
  "hourlyWage": 0,
  "effectiveFrom": "YYYY-MM-DD",
  "sourceUrl": "https://...",
  "checkedAt": "YYYY-MM-DD"
}
```

不得只保存一个永久不更新的数字。

## 2.4 班次与收入日历

日历状态：

```text
已排班
已完成
等待工资
已发工资
临时取消
请假
```

统计：

- 本周工时。
- 本月工时。
- 预计税前收入。
- 已确认工资。
- 交通费。
- 待核对差额。

可以导出个人 CSV 或 `.ics`，不需要连接企业考勤系统。

## 2.5 劳动合同检查表

允许用户上传合同或手动填写，但只定位和解释字段：

```text
雇佣期间
工作地点
工作内容
基本时薪
工资支付日
交通费
休息时间
试用期
加班规则
请假规则
辞职提前通知期
合同更新方式
```

系统结果：

```text
合同中暂未找到“交通费”说明，请查看原文或向雇主确认。
```

不要输出：

```text
合同无效
该条款违法
```

## 2.6 劳动问题证据包

支持用户保存：

- 劳动合同。
- 排班表。
- 工资单。
- 打卡记录。
- 与店长的聊天截图。
- 工作受伤记录。
- 未付工资或临时解雇事件。

时间线示例：

```text
2026/07/03  收到7月排班
2026/07/15  临时要求延长工作
2026/07/25  工资单未计入用户记录的8小时
2026/08/01  向店长询问，尚未回复
```

导出内容：

- 用户填写的事实摘要。
- 事件时间线。
- 工时统计。
- 附件目录。
- 原始附件 ZIP。

导出时避免把推测写成事实。

咨询入口：

- [厚生劳动省：中国语劳动条件咨询](https://www.check-roudou.mhlw.go.jp/soudan/foreigner_chi.html)
- [厚生劳动省：综合劳动咨询窗口](https://www.mhlw.go.jp/general/seido/chihou/kaiketu/soudan.html)
- [劳动条件咨询 Hotline](https://www.check-roudou.mhlw.go.jp/lp/hotline/index.html)

## 2.7 打工日语模板

第一版场景：

- 生病请假。
- 申请换班。
- 确认排班。
- 询问工资单。
- 确认交通费。
- 拒绝无法承担的追加班次。
- 说明可工作时间。
- 提出辞职。
- 索取劳动条件通知书。
- 报告工作受伤。

每条模板包含：

```text
使用场景
礼貌日语
简短日语
中文含义
适合发送给谁
需要替换的变量
需要避免的表达
```

模板必须由用户确认后复制，不自动发送给雇主。

# 3. 留学生食谱

## 3.1 功能定位

不与大型菜谱平台竞争菜谱数量，重点解决：

- 看不懂日本食品包装。
- 不知道食材什么时候应该优先使用。
- 厨房设备有限。
- 预算有限。
- 不熟悉日本计量单位和调理说明。
- 对过敏原、猪肉、酒精、明胶等成分有确认需求。

## 3.2 日本食品标签助手

支持拍摄包装后辅助识别：

- 商品名称。
- 原材料。
- 过敏原。
- 保存方式。
- 加热方式。
- 消费期限和赏味期限。
- 营养成分。
- 内容量。
- 开封后注意事项。

界面示例：

```text
食品标签识别

消费期限：2026/08/09
保存方法：10℃以下冷藏
加热：500W 2分30秒

识别到的过敏原：乳成分、鸡蛋

OCR及翻译可能有误，过敏原请以包装原文及店员确认为准。
```

安全要求：

- 保留原图和原始日文。
- 识别结果必须允许修改。
- 低置信度内容显示“未确认”。
- 不得根据 OCR 结果保证“无过敏原”。
- 对“可能含有”“同一工厂生产”等文字单独展示。
- 不对外食菜品推断不存在某种成分。

官方来源：

- [消费者厅：食物过敏标识信息](https://www.caa.go.jp/policies/policy/food_labeling/food_sanitation/allergy/)
- [消费者厅：食品标识多语言资料](https://www.caa.go.jp/policies/policy/food_labeling/information/pamphlets/)
- [农林水产省：消费期限与赏味期限](https://www.maff.go.jp/j/syokuiku/kodomo_navi/featured/abc2.html)

## 3.3 冰箱库存与优先使用

```text
今天优先使用

鸡肉       消费期限剩1天
豆腐       消费期限剩2天
菠菜       购入后第4天
牛奶       已开封3天
```

库存字段：

```json
{
  "id": "food_001",
  "name": "鸡胸肉",
  "nameJa": "鶏むね肉",
  "quantity": 300,
  "unit": "g",
  "storage": "refrigerated",
  "purchasedAt": "2026-08-06",
  "openedAt": null,
  "bestBefore": null,
  "useBy": "2026-08-08",
  "source": "manual",
  "note": ""
}
```

功能：

- 手动添加。
- 扫描包装辅助添加。
- 拍小票辅助添加。
- 标记开封。
- 冷藏/冷冻状态转换。
- 即将到期提醒。
- 根据现有食材生成候选组合。
- 生成购物清单。

系统只能提醒包装日期与保存信息，不应直接判断已过期食品一定可以食用。

## 3.4 留学生厨房模式

设备筛选：

```text
只有微波炉
只有电饭煲
一口灶
没有烤箱
没有冷冻室
宿舍禁止明火
```

需求筛选：

```text
15分钟以内
预算500日元
一人份
适合带便当
少油烟
容易清洗
可冷冻
消耗临期食品
```

饮食偏好只作为筛选，不作为安全认证：

```text
不吃猪肉
不含酒精调味料
素食倾向
清真饮食倾向
乳糖不耐受
过敏原回避
```

如果配料来源无法确定，显示：

```text
无法确认是否符合你的饮食要求，请查看包装原文或咨询店员。
```

## 3.5 日本调理单位与说明翻译

静态知识库：

```text
大さじ1       15ml
小さじ1        5ml
1合           180ml容量的生米
少々          少量，通常无法精确换算
ひとつまみ     用手指捏取的少量
弱火          小火
中火          中火
強火          大火
水にさらす     放入水中浸泡
粗熱を取る     放置至热气基本散去
```

不要对模糊词强行给出伪精确克数。

## 3.6 营养估算

数据来源：

- [文部科学省：日本食品标准成分表](https://www.mext.go.jp/a_menu/syokuhinseibun/index.htm)
- [文部科学省：食品成分数据库](https://fooddb.mext.go.jp/)

可展示：

- 热量。
- 蛋白质。
- 脂肪。
- 碳水化合物。
- 食盐相当量。
- 膳食纤维。

界面必须标记：

```text
营养值根据标准食品数据估算，实际商品和烹饪结果可能不同。
```

不得根据用户疾病直接生成治疗饮食或替代医生建议。

## 3.7 个人食品价格簿

不依赖超市价格 API，使用用户自己的小票记录：

```text
鸡蛋 10个
本次：¥238
个人历史均价：¥253
购买地点：某超市
```

功能：

- 同一食材不同门店价格记录。
- 单位价格换算。
- 个人历史最低价。
- 本周食材预算。
- 购物清单预计金额。

不要宣称这是整个地区的实时最低价。

## 3.8 地方料理与食品减少浪费

地方料理可引用或链接：

- [农林水产省：うちの郷土料理介绍](https://www.maff.go.jp/j/pr/annual/pdf/kyoudoryouri.pdf)

食品减少浪费参考：

- [农林水产省：食品 Loss 与食品回收](https://www.maff.go.jp/j/shokusan/recycle/syoku_loss/)

使用规则：

- 记录原始出处。
- 不整页复制受版权保护内容。
- 优先做地方料理导航、食材说明和官方页面跳转。
- 自制食谱模板需独立编写。

# 4. 租房避坑

## 4.1 功能定位

帮助用户比较真实入住成本、理解合同字段、记录入居时房屋状态、准备搬家和退租事项。

系统不应：

- 判断某合同条款一定有效或无效。
- 承诺用户一定能拿回押金。
- 对房源或中介做未经证实的欺诈指控。
- 代替律师、不动产从业者或消费者咨询机构。

## 4.2 入居总成本计算器

```text
月租              ¥72,000
管理费             ¥5,000
押金               ¥72,000
礼金               ¥72,000
中介费             ¥79,200
保证会社费用        ¥36,000
火灾保险            ¥18,000
换锁费              ¥22,000
清扫费              ¥44,000
──────────────────
初期费用合计       ¥420,200
```

字段：

```text
rent
managementFee
deposit
keyMoney
agencyFee
guarantorCompanyFee
insuranceFee
keyExchangeFee
cleaningFee
supportServiceFee
otherInitialFee
renewalFee
guarantorAnnualFee
contractTermMonths
earlyCancellationPenalty
```

输出：

- 初期费用。
- 每月固定费用。
- 第一年预计总成本。
- 两年预计总成本。
- 折算月均成本。
- 退租时可能发生但尚未确定的费用。

不得把未确认费用自动视为零。

## 4.3 合同条款定位与解释

允许上传合同，但优先做字段定位：

```text
短期解约违约金
退去通知期限
自动更新/定期借家
固定清扫费
保证会社更新费
火灾保险
24小时支持服务
宠物/吸烟特约
家具损坏费用
禁止事项
```

输出示例：

```text
发现“退去时固定清扫费”条款。
该条款可能产生额外费用，请查看金额、适用条件并向中介确认。
```

禁止输出：

```text
该条款无效
你不需要支付
中介违法
```

官方参考：

- [国土交通省：外国人寻找租赁住宅支持资料](https://www.mlit.go.jp/jutakukentiku/house/jutakukentiku_house_tk3_000017.html)
- [国土交通省：原状恢复纠纷指南](https://www.mlit.go.jp/jutakukentiku/house/jutakukentiku_house_tk3_000021.html)
- [国土交通省：原状恢复 Q&A](https://www.mlit.go.jp/jutakukentiku/house/jutakukentiku_house_tk3_000024.html)

## 4.4 入居拍照证据包

拍摄流程：

```text
房间
  ├─ 墙面
  ├─ 地板
  ├─ 门窗
  ├─ 插座
  └─ 空调

厨房
浴室
厕所
阳台
玄关
设备
```

每条记录：

```json
{
  "room": "洋室",
  "area": "东侧墙壁",
  "issueType": "scratch",
  "descriptionZh": "入居时已有约3cm划痕",
  "descriptionJa": "入居時から約3cmの傷あり",
  "capturedAt": "2026-08-06T14:32:00+09:00",
  "imagePath": "local://...",
  "sentToManagement": false
}
```

功能：

- 自动记录时间。
- 保留原图。
- 为不同房间生成检查清单。
- 用户确认后生成日文说明。
- 导出 PDF 和原图 ZIP。
- 记录是否已发送给管理公司。
- 设置“入住后尽快确认”的提醒。

默认本地存储，上传云端前必须明确告知。

国土交通省指出，入住和退租时确认房屋损耗状态有助于预防原状恢复纠纷：[官方说明](https://www.mlit.go.jp/jutakukentiku/house/jutakukentiku_house_tk3_000020.html)。

## 4.6 灾害风险与避难入口

输入地址后提供官方入口：

- 洪水。
- 内涝。
- 土砂灾害。
- 津波。
- 指定避难所。

官方参考：

- [国土地理院：Hazard Map Portal](https://disaportal.gsi.go.jp/hazardmap/pamphlet/pamphlet.html)

实现边界：

- 第一版优先深链到官方地址查询页面。
- 若嵌入地图或图层，必须核对各图层利用条款。
- 不擅自复制非开放图层。
- 不根据单一图层生成“此房绝对安全/危险”的结论。

## 4.7 搬家任务清单

用户可手动选择适用事项：

```text
[ ] 国民健康保险

[ ] 手机和信用卡地址
[ ] 水电燃气
[ ] 网络开通
[ ] 垃圾日历
[ ] 自行车相关手续
[ ] 邮局转送
```

要求：

- 用户自行确认适用事项。
- 每项可以设置截止时间、状态和备注。
- 具体期限和材料不应仅依赖模型记忆。
- 没有核对官方来源时显示“请确认”。

## 4.8 退租助手

流程：

```text
确认退去通知期限
  ↓
发送退去通知
  ↓
预约立会
  ↓
整理入居时照片
  ↓
拍摄退去状态
  ↓
记录钥匙返还
  ↓
核对清算明细
```

功能：

- 退去通知日期计算。
- 合同条款快捷定位。
- 入住/退租照片对比。
- 清算项目录入。
- 对不理解的费用生成询问日语。
- 导出证据包。

只提示“需要确认的项目”，不直接裁定费用归属。

# 5. 三个模块之间的联动

## 5.1 统一日程


## 5.2 统一预算

```text
本月收入
- 房租
- 水电燃气
- 食材
- 通勤
- 其他固定支出
= 可用生活预算
```

只做个人收支记录，不提供投资、税务或社会保险结论。

## 5.3 打工与食谱联动

- 根据下班时间推荐可完成的简易食谱。
- 夜班前生成便当准备提醒。
- 工作日食谱优先消耗临期食材。
- 将工作地点附近购买的食材加入个人价格簿。

## 5.4 租房与食谱联动

- 根据厨房设备过滤食谱。
- 根据冰箱和冷冻室容量调整采购量。
- 搬家前生成“清空冰箱”计划。
- 入住后建立厨房设备清单。

## 5.5 打工与租房联动

- 房源比较时显示用户手动设置的通勤时间。
- 计算房租占个人预计收入比例，仅作预算参考。
- 搬家时提醒更新雇主登记地址。
- 不把收入预测当成稳定收入证明。

# 6. 隐私与安全要求

三个模块可能涉及敏感数据：

- 在留卡。
- 劳动合同。
- 工资单。
- 银行信息。
- 租赁合同。
- 住宅地址。
- 房间照片。
- 食品过敏信息。

实现要求：

- 默认本地保存敏感附件。
- OCR 前说明文件将在哪里处理。
- 上传外部 AI 前获得明确同意。
- 提供证件号码、银行账号、地址自动遮挡工具。
- 用户可以单独删除附件和识别结果。
- 导出文件前预览包含的敏感信息。
- 日志中不得记录合同全文、证件号码或银行账号。
- 不使用用户文件训练模型，除非有独立、明确且可撤回的同意机制。

# 8. 验收标准

## 8.1 打工助手

1. 用户可以记录两个以上兼职，并查看一周总工时。
2. 跨周班次不会全部计算到同一周。
3. 最低工资显示金额、生效日期和官方来源。
4. 工资检查只显示“需要确认”，不自动作出违法判断。
5. 用户可以导出自己的工时与事件记录。
6. 日语模板不会未经确认自动发送。

## 8.2 留学生食谱

1. 用户可以添加食材、日期和保存状态。
2. 消费期限和赏味期限在界面上明确区分。
3. OCR 结果保留原文并允许修改。
4. 过敏原识别明确提示不能替代包装原文确认。
5. 用户可以根据厨房设备和预算筛选食谱。
6. 营养数据明确标记为估算并注明来源。

## 8.3 租房避坑

1. 入居费用计算包含一次性费用与长期费用。
2. 未确认的费用不会自动按零处理。
3. 合同分析只定位条款，不判断其法律效力。
4. 入居照片包含房间、部位、描述和拍摄时间。
5. 用户可以导出照片与检查记录。
6. 灾害信息回链官方来源，不生成绝对安全结论。
