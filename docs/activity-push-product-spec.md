# 日本留学生娱乐活动推送功能：产品分类与实现参考

> 用途：作为 Claude 或其他开发助手实现“活动推送”功能时的产品需求与数据结构参考。
>
> 目标用户：居住在日本、以中文为主要使用语言，对 K-POP、日本偶像、动漫游戏、角色 IP、舞台音乐剧及线下限定活动感兴趣的留学生。
>
> 文档日期：2026-08-06

---

## 1. 产品目标

帮助用户关注自己喜欢的艺人、作品、角色或品牌 IP，自动聚合日本境内相关活动，并在重要时间节点提供可靠、可执行的提醒。

产品不应只做“社交平台链接导航”，而应优先回答以下问题：

1. 我关注的对象最近有什么活动？
2. 活动在日本哪里举行，距离我多远？
3. 现在需要抽选、购票、预约还是购买周边？
4. 截止时间是什么时候？
5. 留学生参加是否需要日本手机号、日本地址、FC 会员或本人确认？
6. 信息是否来自官方或可信票务渠道？

---

## 2. 分类设计原则

不要把“K-POP、音乐剧、IP 周边、快闪店”全部放在同一级分类里。它们分别回答不同问题：

- **兴趣/IP 分类**：用户关注什么。
- **活动形式**：发生了什么。
- **事件阶段**：为什么现在需要推送。
- **地区与参与条件**：用户能否参加。
- **信息来源等级**：信息是否可靠。

一个活动应支持多维标签。例如：

```text
对象：SEVENTEEN
兴趣大类：K-POP・韩流
活动形式：Fan Meeting
事件阶段：FC 抽选即将截止
地区：东京
参与条件：FC 会员、日本手机号、本人确认
来源：日本官方网站
```

## 5. 推送事件阶段

`event_phase` 决定推送原因和优先级。

| 枚举值 | 推送文案建议 | 默认优先级 |
|---|---|---:|
| `announcement` | 新活动官宣 | 中 |
| `fc_presale` | FC/会员先行开始 | 高 |
| `lottery_open` | 抽选申请开始 | 高 |
| `lottery_ending` | 抽选即将截止 | 最高 |
| `lottery_result` | 中签结果公布 | 最高 |
| `payment_ending` | 付款即将截止 | 最高 |
| `general_sale` | 一般发售开始 | 最高 |
| `first_come_sale` | 先着发售开始 | 最高 |
| `additional_show` | 追加场次/追加席位 | 高 |
| `event_starting` | 活动即将开始 | 中 |
| `event_last_day` | 活动最后一天 | 高 |
| `preorder_open` | 周边预约开始 | 中 |
| `preorder_ending` | 周边预约即将截止 | 高 |
| `release_day` | 商品今日发售 | 中 |
| `restock` | 商品补货/再贩 | 高 |
| `schedule_change` | 时间/场地变更 | 最高 |
| `postponed` | 活动延期 | 最高 |
| `cancelled` | 活动取消 | 最高 |

### 5.1 推荐通知时间

- 新活动官宣：发现后尽快推送一次。
- 抽选/预约开始：开始时推送一次。
- 截止提醒：截止前 72 小时、24 小时、3 小时，可由用户自定义。
- 一般/先着发售：开始前 24 小时、1 小时、开始时。
- 线下活动：前一天晚上及当天出发前。
- 活动变更、延期、取消：确认官方来源后立即推送。

## 6. 留学生专属参与条件

这些字段是本产品区别于普通活动聚合 App 的重点。

| 字段 | 类型 | 说明 |
|---|---|---|
| `jp_phone_required` | boolean/null | 是否要求日本手机号 |
| `jp_address_required` | boolean/null | 是否要求日本地址 |
| `fanclub_required` | boolean/null | 是否为 FC/会员限定 |
| `identity_check` | boolean/null | 是否进行本人确认 |
| `companion_registration` | boolean/null | 是否要求同行者登记 |
| `residency_restriction` | string/null | 是否限制日本在住者 |
| `payment_methods` | string[] | 信用卡、便利店、PayPay 等 |
| `ticket_app` | string/null | eplus、ローチケ、MOALA、AnyPASS 等 |
| `language_support` | string[] | 日文、中文、英文、韩文 |
| `foreigner_friendly` | boolean/null | 是否提供海外用户入口或多语言说明 |
| `age_restriction` | string/null | 年龄限制 |
| `drink_fee` | number/null | Live House 是否另收饮料费 |
| `seat_type` | string/null | 指定席、整理番号、全站席等 |

不知道时使用 `null`，不要默认显示“无需”。前台统一显示“未确认”。

示例：

```text
FC 限定｜本人确认あり｜日本手机号必需｜便利店付款可
```

## 7. 信息来源可信度

活动卡片应显示来源及可信度，不应将官方、票务平台和社交帖子平级展示。

| 等级 | 来源类型 | 示例 | 使用规则 |
|---|---|---|---|
| S | 官方来源 | 官方网站、官方 App、官方 X、主办方公告 | 可直接作为确认信息 |
| A | 正式票务/场馆 | ぴあ、eplus、ローチケ、LivePocket、TIGET、TicketDive、场馆官网 | 可作为时间和售票依据 |
| B | 官方合作方/商业设施 | PARCO、Animate、Loft、联名咖啡运营方 | 可用于线下活动与商品信息 |
| C | 专业媒体 | Kstyle、舞台ナタリー、Anime media | 用于发现，重要信息应回查官方 |
| D | 用户内容/社交平台 | 小红书、微博、普通 X 帖子 | 只作为线索，必须标记“非官方” |

### 7.1 来源展示规则

```text
来源：SEVENTEEN Japan Official　✓ 官方
```

或：

```text
来源：用户分享　未验证
```

社交平台按钮可以保留在详情页的“相关讨论”区域，但不要放在活动卡片的主要行动区域。

## 9. 去重与聚合规则

同一活动经常会被官网、票务平台、场馆和媒体重复发布。

建议按以下信息判断是否为同一活动：

1. 标准化后的活动名称。
2. 主体/IP 是否相同。
3. 举办日期与场馆是否相同。
4. 官方活动 URL、票务活动 ID 是否一致。
5. 标题相似度及时间差。

合并后保留多个来源，但主来源优先级为 `S > A > B > C > D`。

当不同来源冲突时：

- 优先使用更新时间更近的官方来源。
- 标记“信息有变更”，不要静默覆盖用户已经收藏的日期。
- 若活动时间或取消状态发生变化，应触发高优先级通知。

## 10. 推荐与排序逻辑

推荐分数可以从以下维度计算：

```text
推荐分数 =
  关注对象匹配 × 40%
  兴趣分类匹配 × 20%
  地区/距离匹配 × 15%
  时间紧迫度 × 15%
  来源可信度 × 10%
```

基本规则：

- 用户明确关注的 IP/艺人优先于大类兴趣。
- 即将截止的抽选、付款和先着发售优先于普通新闻。
- 同一活动不要因多个来源重复占据 Feed。
- 用户屏蔽某分类或地区后，不应继续发送普通推荐。
- 取消、延期和用户已报名活动的变更通知不受普通屏蔽影响。

## 11. 页面信息架构

### 11.1 页面顶部

标题建议：

```text
活动推送
イベント
```

搜索框建议：

```text
搜索 IP、艺人或作品
例：ちいかわ、SEVENTEEN、宝塚
```

### 11.2 “我的关注”区域

只显示已关注对象和推荐关注对象：

```text
我的关注 4
[三丽鸥 ×] [吉伊卡哇 ×] [Hello Kitty ×] [库洛米 ×]
```

推荐标签应有明确理由：

```text
因为你关注了三丽鸥
[玉桂狗 +] [美乐蒂 +] [布丁狗 +]
```

不要使用设备相关 Emoji 作为长期图标系统。正式版本建议使用统一线性图标或 IP 授权图片。

### 11.3 Feed 快捷筛选

```text
为你推荐｜本周活动｜抽选截止｜新品发售
```

可增加地区筛选：

```text
东京｜神奈川｜千叶｜埼玉｜关西｜线上
```

### 11.4 活动卡片结构

```text
[官方] [抽选即将截止]

SEVENTEEN FANMEETING 2026
K-POP・Fan Meeting

9月10日 18:00
东京巨蛋｜水道桥站

截止：8月10日 23:59　剩余 2 天

FC限定｜本人确认｜日本手机号必需

[加入日程] [查看官方]

```

卡片的第一主按钮应根据阶段变化：

- 抽选阶段：`申请抽选`
- 售票阶段：`购买门票`
- 预约阶段：`立即预约`
- 普通活动：`查看详情`
- 已收藏活动：`加入日程` 或 `设置提醒`

### 11.5 详情页模块

建议顺序：

1. 标题、官方状态、活动标签。
2. 日期、场馆、地图、最近车站。
3. 抽选/售票阶段和倒计时。
4. 参加条件与留学生注意事项。
5. 价格、席种、付款方式。
6. 官方链接与票务链接。
7. 设置提醒、加入日程。
8. 相关周边或关联活动。
9. 社交平台讨论，明确标注非官方。

## 12. 当前设计稿的调整建议

当前设计将“官方、小红书、微博、X、Google 活动”放在卡片主要区域，更接近平台导航。建议调整为：

- 首页主体从“平台入口”改为“真实活动与截止事项”。
- 来源按钮移动至详情页或卡片底部。
- 将“上新・热帖直达”改为“最新动态”或“关注更新”。
- 活动卡片必须显示时间、地点、阶段和剩余时间。
- 官方信息使用明显但克制的“官方/已验证”标签。
- 小红书、微博、普通 X 帖子统一放入“相关讨论”，不可显示为已确认活动。
- 中文为主要语言时，日文只作为辅助标签，不要让同一页面中语言层级混乱。
- 关注对象、兴趣分类和活动 Feed 应分成不同模块，避免用户不知道添加的是 IP 还是活动类型。

## 13. MVP 实现范围

### P0：第一版必须完成

- 添加、删除和搜索关注对象。
- 对象支持中文、日文和英文别名。
- 一级兴趣分类和热门快捷标签。
- 活动 Feed 与详情页。
- 活动形式、事件阶段、地区筛选。
- 官方/非官方来源标识。
- 收藏活动、加入日程、截止提醒。
- 基础去重。
- 日本手机号、FC、本人确认等参与条件字段。

### P1：第二阶段

- 个性化推荐排序。
- 地理距离与最近车站。
- 抽选、付款、开售的多阶段自动提醒。
- 同一活动多来源合并。
- 变更、延期和取消提醒。
- 票务平台深链。

### P2：后续能力

- 自动解析官网和官方社交账号。
- 中文自动摘要与规则解释。
- 海外用户可购票能力判断。
- 票价/预算过滤。
- 好友同行、拼场和活动分享。
- 周边愿望单、预约及补货提醒。

## 14. MVP 验收标准

1. 用户可以搜索并关注“ちいかわ / Chiikawa / 吉伊卡哇”，系统识别为同一对象。
2. 用户可以分别选择“K-POP”兴趣和“Fan Meeting”活动形式。
3. 活动卡片至少显示标题、日期、地区、活动形式、当前阶段和来源。
4. 抽选截止活动可以显示倒计时并设置提醒。
5. 非官方社交帖子不能显示为“官方活动”。
6. 同一场活动来自官网和票务平台时，Feed 中只出现一张主卡片。
7. 参与条件未知时显示“未确认”，不能错误显示“无需”。
8. 活动取消或时间变更后，已收藏用户会收到高优先级通知。
9. 用户可以屏蔽不感兴趣的大类、活动形式或地区。
10. 页面在手机宽度下保持清晰，核心截止信息无需进入详情页即可看到。
