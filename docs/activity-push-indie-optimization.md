# 活动推送页面：个人开发者可实现的功能优化规格

> 用途：交给 Claude 优化现有“活动推送 / 最新动态”页面。
>
> 配套文档：`docs/activity-push-product-spec.md`
>
> 核心约束：以个人开发者能够合法、稳定实现的能力为边界，不依赖企业认证、平台专属 API、实时票务库存或大规模社交平台抓取。
>
> 文档日期：2026-08-06

---

## 1. 核心判断

当前页面显得寡淡，主要原因不是配色不足，而是信息层级仍然是“去哪里搜索”，没有形成明确的用户任务。

当前主要内容：

```text
关注对象
  ├─ 官方站
  ├─ Google 活动
  ├─ 小红书
  ├─ 微博
  └─ X
```

这更接近“外部链接收藏夹”。优化后的页面应回答：

```text
今天有什么需要处理？
哪个抽选即将截止？
我已经申请到哪一步？
参加活动需要准备什么？
怎样加入日历并避免错过？
```

推荐产品定位：

> 面向日本留学生的“推し活动个人工作台”：收藏活动、看懂抽选规则、管理截止时间和出行准备。

## 2. 权限边界

### 2.1 可以稳定实现

- 用户手动添加活动。
- 用户粘贴官网、票务或社交平台链接。
- 读取公开网页基础元数据，并由用户确认。
- 本地保存关注对象、活动、状态、预算和笔记。
- 根据时间生成倒计时和提醒规则。
- 生成标准 `.ics` 日历文件。
- 跳转到官方页面、地图、换乘和票务平台。
- 使用用户选择的分类和地区做本地推荐。
- 使用 PWA、Service Worker 和标准 Web Push 做可选通知。
- 展示留学生购票条件和日文术语解释。

### 2.2 不作为核心依赖

- X、微博、小红书的完整内容 API。
- 需要企业认证的官方账号接口。
- 实时票务库存、座位和动态价格。
- 自动购票、自动抽选或抢票。
- 大规模、高频率抓取第三方网站。
- 未授权转载活动海报、图片或完整正文。
- 将普通用户帖子标记为“官方信息”。

原则：平台数据拿不到时，仍然保证“用户自己保存的活动可以完整管理”。

## 3. 推荐页面结构

页面不再以“关注对象折叠列表”为主体，改成四层结构。

```text
活动推送
├─ 今日行动摘要
├─ 快捷筛选
├─ 活动时间线 / Feed
└─ 我的关注对象
```

### 3.1 顶部：今日行动摘要

使用 2×2 数据卡或横向滑动卡片：

```text
今天需要处理 2 件

[1] 抽选即将截止
[1] 等待付款
[3] 本周活动
[2] 即将发售
```

点击数字进入对应筛选结果。

建议状态颜色：

- 红色：截止、取消、重要变更。
- 橙色：待付款、即将开售。
- 蓝色：即将开始、日程信息。
- 绿色：已申请、已预约、已完成。
- 紫色：周边、联名、IP 活动。

### 3.2 快捷筛选

第一行：

```text
为你推荐｜即将截止｜本周活动｜新品发售
```

第二行可横向滚动：

```text
全部｜K-POP｜地偶｜动漫｜角色IP｜音乐剧｜东京｜关西｜线上
```

### 3.3 主体：活动 Feed

Feed 展示真实活动或用户创建的活动，不展示单纯的平台按钮。

活动卡片示例：

```text
[官方] [抽选剩余 2 天]

SEVENTEEN FANMEETING 2026
K-POP・Fan Meeting

9月10日 18:00
东京巨蛋｜水道桥站

截止：8月10日 23:59

FC限定｜本人确认｜日本手机号必需

[申请抽选] [加入日程]

来源：SEVENTEEN Japan Official ✓
```

没有海报时，卡片封面使用：

- 分类渐变色。
- 统一线性图标。
- IP 或艺人首字母。
- 用户上传的本地图片。

不要依赖设备 Emoji 作为正式图标系统。

### 3.4 底部：我的关注对象

关注对象从页面主体降级为管理模块：

```text
我的关注 4
[三丽鸥] [吉伊卡哇] [Hello Kitty] [库洛米]

[管理关注] [添加对象]
```

点击对象进入对象详情页，再查看：

- 最近活动。
- 即将截止。
- 官方来源。
- 相关讨论。

“官方站、小红书、微博、X”保留在详情页的来源区，不作为首页主内容。

## 4. P0 功能：第一版优先实现

### 4.1 今日 / 本周行动面板

根据本地活动数据实时计算：

- `lotteryDeadlineCount`
- `paymentDeadlineCount`
- `thisWeekEventCount`
- `releaseSoonCount`
- `scheduleChangedCount`

排序优先级：

```text
取消/变更
> 付款截止
> 抽选截止
> 先着开售
> 当日活动
> 本周活动
> 新品发售
> 普通资讯
```

### 4.2 活动状态管理

用户可以为每个活动设置状态：

```text
interested       想去
applied          已申请
won              已中签
lost             未中签
payment_pending  待付款
paid             已付款
scheduled        已加入日程
attended         已参加
cancelled        已放弃/取消
```

对于地偶、Live House 活动，可以增加：

```text
reserved         已预约
queue_known      整理番号已出
benefit_planned  特典会计划已记录
```

状态变化只保存为用户私有数据，不依赖第三方平台。

### 4.3 手动创建活动

必填字段：

- 活动名称。
- 日期或截止时间。
- 活动类型。

选填字段：

- 关注对象/IP。
- 场馆和地区。
- 官方链接。
- 票务链接。
- 价格。
- 参加条件。
- 备注。

### 4.4 粘贴链接创建活动

建议交互：

```text
粘贴 URL
  ↓
读取 title / description / og:image
  ↓
若页面含 Event JSON-LD，读取日期、地点和票务字段
  ↓
展示确认表单
  ↓
用户修改并保存
```

要求：

- 解析失败时允许纯手动输入。
- 保存原始 URL。
- 所有自动识别字段必须允许修改。
- 不因解析结果自动标记“官方”。
- 来源可信度需要单独判断或由用户选择。

### 4.5 日历导出

生成标准 `.ics` 文件，至少包含：

```text
SUMMARY
DTSTART
DTEND
LOCATION
DESCRIPTION
URL
VALARM
```

支持两个不同日程：

1. 活动举办时间。
2. 抽选、付款或预约截止时间。

按钮文案：

```text
加入日历
添加截止提醒
```

### 4.6 留学生参加条件卡

```text
参加条件

日本手机号       必需 / 不需要 / 未确认
日本地址         必需 / 不需要 / 未确认
FC会员           必需 / 不需要 / 未确认
本人确认         有 / 无 / 未确认
同行者登记       有 / 无 / 未确认
付款方式         信用卡 / 便利店 / 其他
电子票App        AnyPASS
语言支持         日文
```

未知值使用 `null`，前台显示“未确认”，不能默认显示“不需要”。

### 4.7 日文票务术语帮助

内置静态知识库即可，无需外部权限。

第一版建议覆盖：

| 日文 | 中文解释 |
|---|---|
| 抽選 | 抽签，不是先到先得 |
| 先着 | 先到先得 |
| 一般発売 | 面向普通用户公开售票 |
| FC先行 | 粉丝俱乐部会员优先申请 |
| 整理番号 | 决定入场顺序，通常不是座位号 |
| 本人確認 | 入场时核对本人证件 |
| 同行者登録 | 需要提前登记同行者信息 |
| 分配 | 将电子票发送给同行者 |
| 発券 | 取票或生成电子票 |
| ドリンク代 | Live House 现场另付饮料费 |
| 受注生産 | 在预约期结束后按订单生产 |
| 再販 | 再次销售 |

## 5. P1 功能：增强留存

### 5.1 场地出行助手

活动详情增加：

- 最近车站。
- 地图深链。
- 换乘搜索深链。
- 建议提前到达时间。
- 末班车提醒。
- 是否站席。
- 是否另收饮料费。
- 储物柜/行李提醒。
- 当天天气链接。

不必在第一版接入复杂地图 API，先使用普通地图 URL 和换乘 URL。

### 5.2 活动准备清单

默认清单：

```text
[ ] 在留卡/护照
[ ] 电子票已登录
[ ] 手机电量充足
[ ] 充电宝
[ ] 现金/饮料费
[ ] 应援棒
[ ] 会员卡
[ ] 同行者票已分配
```

用户可以编辑模板，并为不同类型活动保存不同清单。

### 5.3 推し活预算

字段：

```text
ticketPrice       门票
serviceFee        票务手续费
transportCost     交通
accommodationCost 住宿
goodsBudget       周边
drinkFee          饮料费
otherCost         其他
```

卡片示例：

```text
门票          ¥9,800
手续费        ¥1,320
交通          ¥960
周边预算      ¥5,000
饮料费        ¥600
────────────────
预计合计      ¥17,680
```

月度统计：

```text
本月预算 ¥30,000
已计划   ¥24,680
剩余     ¥5,320
```

### 5.4 个人推荐

推荐只依赖用户数据即可：

```text
推荐分数 =
关注对象匹配 × 40%
+ 兴趣分类匹配 × 20%
+ 地区匹配 × 15%
+ 日期可参加程度 × 10%
+ 预算匹配 × 5%
+ 时间紧迫度 × 10%
```

推荐卡必须说明理由：

```text
因为你关注了三丽鸥
因为你常看东京的角色 IP 活动
距离活动地点约 35 分钟
```

## 8. 视觉优化建议

### 8.1 避免所有卡片完全同构

建议形成三种视觉层级：

1. **摘要卡**：小尺寸、数字突出。
2. **紧急活动卡**：显示倒计时色条和主行动按钮。
3. **普通活动卡**：紧凑列表形式。

### 8.2 使用状态驱动颜色

```text
critical   #C95B55  截止、取消、变更
warning    #D89A43  待付款、即将发售
info       #5F87B2  即将开始、普通日程
success    #6F9B70  已申请、已完成
goods      #8B78AD  周边、联名、IP
neutral    #87796C  普通说明
```

实际实现时应转换为项目 Design Token，并保证文字对比度。

### 8.3 卡片必须有“视觉锚点”

至少使用以下一项：

- 剩余时间大数字。
- 日期块。
- 分类色条。
- IP 首字母封面。
- 统一类别图标。
- 用户提供的图片。

### 8.4 文案层级

```text
一级：活动标题
二级：日期、地点、截止状态
三级：分类、参与条件、来源
```

不要让平台名称比活动标题更醒目。

## 9. 空状态设计

没有自动活动数据时，页面也必须有可操作价值。

```text
还没有保存活动

粘贴官网或票务链接，
就能管理截止时间和参加准备。

[粘贴活动链接]
[手动创建活动]
```

关注对象没有动态时：

```text
暂未发现新的官方活动

你仍可以：
[打开官方网站]
[添加已知活动]
[设置关键词提醒]
```

不要用大量空白或单纯的平台按钮填充空状态。

## 10. 验收标准

1. 页面打开后无需展开关注对象，就能看到最近的截止事项。
2. 活动卡片至少显示标题、日期、地区、阶段和来源。
3. 用户能手动创建活动，不依赖任何第三方平台授权。
4. 用户粘贴链接后，即使自动解析失败，也能进入手动确认表单。
5. 用户可以将活动和截止时间分别导出到日历。
6. 用户可以更新活动状态，并在页面看到状态变化。
7. 参加条件未知时显示“未确认”，不能错误显示“不需要”。
8. 普通社交帖子不能显示为“官方”。
9. 同一活动不会因多个来源重复占据 Feed。
10. 没有海报图片时页面仍具有明确视觉层级。
11. 页面适配手机宽度，截止时间和主按钮无需横向滚动。
12. 空状态提供“粘贴链接”和“手动创建”两个明确行动。

## 11. 推荐实施顺序

### Sprint 1

- 页面结构重排。
- 今日行动摘要。
- 活动卡片与筛选。
- 本地模拟活动数据。
- 关注对象降级到管理模块。

### Sprint 2

- 手动创建活动。
- 粘贴链接确认流程。
- 活动状态管理。
- ICS 日历导出。
- 留学生参加条件卡。

### Sprint 3

- 活动准备清单。
- 预算管理。
- 场地出行助手。
- PWA 通知。
- 个性化推荐和推荐理由。

## 12. 给 Claude 的执行提示词

```text
请先阅读：
1. docs/activity-push-product-spec.md
2. docs/activity-push-indie-optimization.md

然后检查当前项目中活动推送页面的实现、样式系统、数据存储方式和已有组件。

目标：在个人开发者权限范围内，把当前“关注对象＋外部平台按钮”页面优化为“推し活动个人工作台”。

本轮优先实现：
1. 今日行动摘要。
2. 快捷筛选。
3. 具有截止状态、日期、地区、参与条件和来源的活动卡片。
4. 活动状态管理。
5. 手动创建活动和空状态。
6. 将关注对象与外部平台入口降级为辅助模块。

实现要求：
- 先说明当前页面所在文件、技术栈和将修改的文件。
- 复用现有设计语言，但增强信息层级与状态色彩。
- 不接入需要企业认证的第三方 API。
- 不实现对 X、微博、小红书的大规模抓取。
- 不使用未经授权的远程海报作为页面成立的前提。
- 分类、状态、来源等级和术语表必须放在独立配置中。
- 使用合理的模拟数据完成页面交互。
- 保留中文主界面，日文作为辅助信息。
- 不能破坏现有首页、日程和“我的”导航。
- 完成后运行项目现有构建或测试命令。
- 汇报修改文件、功能结果、验证结果和仍未实现的部分。

如果项目代码与文档设想冲突，优先做最小可行改造，并说明取舍，不要擅自重构整个项目。
```

## 13. 相关开放标准参考

- [Schema.org Event](https://schema.org/Event)：公开网页可能使用的活动结构化数据。
- [RFC 5545 iCalendar](https://www.rfc-editor.org/info/rfc5545/)：跨平台日历事件格式。
- [WebKit：iOS/iPadOS Home Screen Web Push](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)：PWA 推送说明。
- [MDN Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)：标准 Web Push 接口。
- [MDN Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API)：使用系统分享面板分享活动链接。
