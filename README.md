# 🗾 日本生活小助手 Agent

> 一个面向**在日中国留学生**的 AI 生活助手 —— 用 Agent + 自有知识库(RAG),把「日语看不懂、不知道该干嘛」的高频生活痛点,变成一句话就能问清楚的对话。

这是一个**产品经理向的 AI 小项目**:重点不在炫技,而在于展示「发现真实痛点 → 拆解场景 → 用 AI 能力对症设计 → 可落地的技术选型」这条完整链路。

---

## 1. 为什么做这个(产品动机)

在日本留学,最折磨人的往往不是学业,而是**生活里那些没人教、日语又看不懂的小事**:

- 一个塑料瓶该扔哪类?这个区周几收?—— 各区规则还不一样。
- 感冒了想看病,日本分科极细,到底挂「内科」还是「呼吸器内科」?到了医院怎么跟医生说?
- 想加入国民健康保险,要带哪些材料、去哪个窗口、能不能网上预约?

这些问题的共同点:**答案高度本地化、碎片化,且藏在日语官网里**。通用大模型能聊,但常常「听起来对、细节错」——因为它不知道你在哪个区、不知道最新规则。

**产品洞察:** 这类问题的价值不在「语言生成」,而在「把准确的本地知识,用你能听懂的方式说出来」。所以核心不是更强的模型,而是**一个对症的知识库 + 会查它的 Agent**。

---

## 2. 目标用户与场景(MVP 聚焦)

初期不贪多,聚焦最高频、最痛的三个场景:

| 场景 | 用户口语提问 | Agent 做什么 |
|------|------------|------------|
| 🗑️ 垃圾分类 | 「新宿区的塑料瓶怎么扔?」 | 判类别 + 给所在区收集日与规则 |
| 🏥 看病分诊 | 「发烧咳嗽该挂什么科?」 | 中文症状 → 推荐科室 → 生成**日语症状卡** |
| 🏛️ 行政陪办 | 「加入健康保险要带啥?」 | 材料清单 + 窗口 + 能否网上预约 + 避坑提醒 |

**典型用户画像:** 刚落地半年内的留学生,日语 N4–N3,遇事第一反应是「问学长 / 翻小红书」,信息零散且不一定准。

---

## 3. 核心设计:为什么要挂「自己的知识库」

这是本项目最想讲清楚的一点,也是 AI 产品设计里最容易被忽略的判断:

> **通用大模型负责「理解意图 + 组织语言」,事实必须来自我们自己的结构化知识库。**

如果全靠模型记忆,会出现两类致命问题:一是**编造**(把 A 区规则说成 B 区的),二是**过时**(规则/金额早变了)。所以我把知识拆成两层,让模型「只做它擅长的事」:

- **结构化知识**(垃圾/行政/医疗):用字段精确查询,保证「某物 → 某类」「某业务 → 某材料」不出错。
- **独特小知识 Tips**(避坑经验):自由文本,用轻量语义检索补充本地化提醒(比如「大医院初诊没转诊信要多付 5000 日元」)。

**产品收益:** 知识库可以独立更新维护、可以按区扩展、出错可追溯到具体数据条目 —— 这比「重新训练模型」现实得多,也是真实产品会走的路。

## 4. 技术架构(Agent + RAG)

```
用户一句话
   │
   ▼
┌─────────────────────────────┐
│  LLM (Gemini 免费层, 走OpenAI │  ← 理解意图,决定调用哪个工具
│  兼容接口) system约束:先查库  │
└──────────────┬──────────────┘
               │ tool_use (function calling)
        ┌──────┴───────┬───────────────┬──────────────┐
        ▼              ▼               ▼              ▼
  search_gomi    search_admin   triage_medical   search_tips
        │              │               │              │
        ▼              ▼               ▼              ▼
┌─────────────────────────────────────────────────────────┐
│      自有知识库 knowledge_base/*.json (RAG 检索层 kb.py)   │
└─────────────────────────────────────────────────────────┘
               │ tool_result 回喂
               ▼
   LLM 基于知识库结果,用口语中文 + 关键日语词组织最终回答
```

这就是一个**完整的 Agent 循环(agentic loop)**:模型自主决定「要不要查、查哪个、查几次」,而不是写死的 if-else。这正是「AI 产品能力」区别于「调一次 API」的地方。

### 目录结构

```
jp-life-agent/
├── README.md              产品文档(你正在看的)

│   ├── admin.json         行政手续:业务/材料/窗口/预约
│   ├── medical.json       分诊:症状→科室 + 日语症状卡模板
│   └── tips.json          独特小知识(供语义检索)

```

## 5. 快速开始

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 领取免费 Gemini key(邮箱登录,不要信用卡):
#    https://aistudio.google.com/apikey
export GEMINI_API_KEY=AIza_xxxx
#    不配 key 也能跑:自动进入 mock 模式演示检索链路

# 3. 一键看 3 大场景演示
python demo.py

# 4. 或进入交互问答
python cli.py

# 5. 只测知识库检索逻辑(纯离线,无需任何 key)
python src/kb.py

# 6. ★ 移动端可视化网页(推荐用于面试展示)
python server.py          # 浏览器打开 http://127.0.0.1:5001
```

### 移动端 Web 界面

`python server.py` 启动一个 Flask 后端(复用同一个 Agent),打开 `http://127.0.0.1:5001` 即是**手机样式的聊天界面**:三大场景快捷入口、气泡对话,并且会把「Agent 调用了哪个知识库工具」实时渲染成 chip(如 `🗑️ 已查询 垃圾分类知识库`)——把 RAG 检索过程可视化,是面试展示的最佳形态。

> 想在真手机上体验:手机连同一 WiFi,访问电脑局域网 IP(如 `http://192.168.x.x:5001`);Chrome 手机模式(F12 → 手机图标)也能直接预览。

**默认用 Gemini 免费层**,通过其 OpenAI 兼容接口调用。想换供应商(Groq / DeepSeek / OpenRouter)只需在 `.env` 改 `LLM_BASE_URL` + `JP_AGENT_MODEL` 两行,代码不用动——见 `.env.example`。

**双模式设计**:未配置 key 时自动降级为 mock,直接展示「Agent 挑了哪个工具、从知识库查到什么」——面试时不依赖网络也能演示核心链路;配置 key 后即为真实自然语言回答。

## 6. 演示话术(面试用)

1. **先跑 `python demo.py`**,指着终端里的 `🔧 调用知识库工具` 那一行说:
   > "注意这里 —— 模型没有直接答,而是**自己决定**去查我的垃圾分类库,拿到新宿区的收集日后才回答。事实全部来自我维护的知识库,不是模型瞎编。"
2. **强调分区差异**:同样问塑料瓶,新宿区和丰岛区规则不同(一个单收、一个并入可燃)——说明「为什么通用模型不够,必须挂本地知识库」。
3. **切到 `cli.py` 现场问答**,让面试官随便问,展示 Agent 的鲁棒性。
4. **落到产品判断**:讲第 3 节「模型做语言、知识库做事实」的取舍,以及第 7 节的迭代规划。

## 7. 产品迭代规划(Roadmap)

| 阶段 | 内容 |
|------|------|
| **V1(当前)** | 3 场景 MVP,结构化知识库 + Agent 检索,命令行形态 |
| V1.5 | 知识库换成向量库(如 embedding + 相似度检索),提升长尾问题召回 |
| V2 | 接入拍照输入(垃圾/说明书/症状 OCR),对应原始需求里的「拍照→识别」 |
| V2 | 补上「快手食谱」「活动推送」「打工助手」等剩余场景 |
| V3 | 小程序 / 轻量 App 形态,做定位自动识别所在区,推送收集日提醒 |
| 持续 | 知识库运营化:按区众包更新、标注来源与更新时间、可信度分级 |

## 8. 已知边界与诚实说明

- 知识库为**示例数据**(基于东京都常见规则整理),真实上线需接各区役所官方数据并标注更新时间。
- 医疗分诊**仅供参考、不构成诊断**,已在代码与回答中强制加入免责声明与急救电话(119 / #7119)。
- 当前检索为轻量字符级打分(无需外部 embedding,保证开箱即跑);生产环境建议升级为向量检索。
